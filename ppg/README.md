# HALO PPG analysis

Offline research prototype using NeuroKit2's Elgendi PPG processing and template
quality. Run commands below from this directory with the existing virtual
environment, or install `requirements.txt` into your own environment.

**For your photographed Nano ESP32 + Gravity SEN0518, start with
[USE_GRAVITY.md](USE_GRAVITY.md) and `record_gravity.py`.** This records the
module's reported heart rate and SpO2. PRV remains explicitly unavailable with
that processed-output interface; it is not inferred from slow BPM readings.

For an ESP32-connected MAX30102, use the [sensor connection guide](CONNECT_SENSOR.md)
and `record_max30102.py`. It records raw red/IR data over USB and automatically
runs resting PRV analysis after capture. No SVRi output is generated by that workflow.
The user's photographed sensor is a **Gravity SEN0518 V1.0**, whose documented
processed-output interface is not supported by this raw-PPG recorder. The guide
records this limitation and the confirmed Nano ESP32/SEN0518 wiring; raw access
or a raw-output breakout is needed to complete the live PRV workflow.

## Pulse variability / HRV surrogate

```sh
.venv/bin/python halo_ppg.py --csv recording.csv --fs 100 --out results
```

The CSV must contain `ir` (or use `--channel red`). Optional `time_s` must be
finite, strictly increasing, and consistent with `--fs`. Use the actual acquisition
rate. `--signal-format processed` disables ADC clipping checks for transformed
signals; `auto` only infers this from negative samples and is a heuristic.

PPG measures **pulse rate variability (PRV)**. These statistics are HRV
surrogates, not measurements of ECG normal-to-normal intervals. The existing
RMSSD and SDNN calculations have been extended with the following fields in
both `window_features.csv` and the dedicated `hrv_features.csv`:

| Field | Definition |
| --- | --- |
| `prv_rmssd_ms` | Root mean square of successive interval differences, ms |
| `prv_sdnn_ms` | Sample standard deviation of pulse intervals, ms; conventionally named SDNN, but these are not verified ECG NN intervals |
| `prv_sdsd_ms` | Sample standard deviation of successive interval differences, ms |
| `prv_pnn20_pct` | Percentage of successive interval pairs differing by **more than** 20 ms |
| `prv_pnn50_pct` | Percentage of successive interval pairs differing by **more than** 50 ms |
| `prv_cvnn` | SDNN / mean interval, dimensionless |
| `prv_cvsd` | RMSSD / mean interval, dimensionless |
| `prv_lnrmssd` | Natural log of RMSSD expressed in ms; blank if RMSSD is zero |

The pNN denominator is the number of successive interval pairs. Standard
deviations use `ddof=1`. No frequency-domain or autonomic-balance interpretation
is supplied.

`--window` controls the original general feature windows. `--hrv-window`
independently controls the dedicated variability report; both default to 60 s.
For five-minute variability windows:

```sh
.venv/bin/python halo_ppg.py --csv recording.csv --fs 100 --hrv-window 300 --out results_5min
```

Compare results using the same duration and acquisition conditions. The 60 s
default supports the existing short recordings; it is not interchangeable with
five-minute HRV measurements. At 40 Hz, peak timing is quantized to 25 ms, which
can materially affect successive-difference metrics and pNN thresholds.
Upsampling does not restore timing information missing from the original signal.

All reports reject windows with low median template quality, clipping/flat input,
fewer than five peaks, intervals outside 333–1500 ms, or intervals deviating more
than 25% from the window median. The dedicated variability report additionally
requires:

- A complete window of at least 60 s.
- No edge without detected peaks longer than 1.5 s.
- At most 5% of samples below the template-quality threshold or with missing quality.

Rejected variability fields are blank, with `accepted=False` and a reason.
There is no interval deletion, ectopic correction, interpolation, or joining
across rejected windows. These conservative checks can reject real physiological
variation and cannot establish normal sinus rhythm. Inspect peaks and compare
with ECG before interpreting the results. Quality acceptance is preliminary.
Trailing incomplete windows are omitted; a recording shorter than one variability
window produces an explicit unavailable row.

## Systemic vascular resistance index (SVRi)

SVRi requires external hemodynamic measurements. It cannot be calculated from
the existing optical waveform, pulse amplitude, or heart rate alone.

```text
SVRi = 80 × (MAP − CVP) / CI          [dyn·s·cm⁻⁵·m²]
CI = cardiac output / body surface area
```

Supply contemporaneous measurements relevant to the analyzed recording:

```sh
# Illustrative values only: MAP=90 mmHg, CVP=5 mmHg, CI=2.5 L/min/m²
.venv/bin/python halo_ppg.py --demo --map-mmhg 90 --cvp-mmhg 5 --cardiac-index 2.5 --out example_ci

# Equivalent example: CO=5 L/min and BSA=2 m²
.venv/bin/python halo_ppg.py --demo --map-mmhg 90 --cvp-mmhg 5 --cardiac-output 5 --bsa 2 --out example_co
```

Both examples yield **2720 dyn·s·cm⁻⁵·m²**. These are examples of arithmetic,
not sensor-derived estimates or patient measurements. The two cardiac-input
forms are mutually exclusive. CVP is mandatory and is never assumed to be zero;
finite negative measured CVP is supported. MAP and cardiac inputs must be finite
and positive, and CVP must be lower than MAP. Partial inputs are errors.

`hemodynamics.csv` contains one external measurement set per run, with input
values, derived CI if applicable, SVRi, units in the column name, and status.
It is independent of PPG quality acceptance and is not a beat-by-beat or
window-varying estimate. With no measurements, SVRi stays blank and the status
explains the missing inputs. Blood pressure alone is insufficient. The included
datasets do not provide all inputs required to validate SVRi.

## Outputs and existing datasets

- `processed_signals.csv`: raw/cleaned PPG, quality and NeuroKit fields.
- `detected_peaks.csv`: peak samples and timestamps (preserves `time_s` origin).
- `window_features.csv`: original window report with added variability columns.
- `hrv_features.csv`: dedicated PRV report with coverage, quality and timing resolution.
- `hemodynamics.csv`: externally supplied hemodynamics and calculated/unavailable SVRi.
- `analysis_metadata.json`: parameters, provenance, formula and unused trailing duration.
- `ppg_first_30s.png`: original signal/peaks/quality plot.

Window boundaries are relative to recording start; peak timestamps and processed
signal timestamps preserve the input time origin. Original outputs are overwritten
when the same `--out` is reused; use a new directory to retain earlier analyses.

The existing `HALO_Real_PPG_Dataset/run_one.py` and `run_all.py` automatically
receive the new default outputs. Their nominal sampling rate is 40 Hz; source
timestamps are retained but not verified, and the compatibility name `ir` does
not confirm wavelength. For explicit settings, call the main script directly:

```sh
.venv/bin/python halo_ppg.py --csv HALO_Real_PPG_Dataset/prepared/PPG_subj_01_forehead.csv --fs 40 --signal-format processed --out subject_01_new
```

`PhysioNet_PPG/validate_physionet.py` now uses the shared variability formulas
and compares HR, SDNN, RMSSD, SDSD, pNN20 and pNN50 with annotated ECG. Its
comparison uses uncorrected intervals without the main pipeline's quality gates;
it measures exploratory discrepancies, not clinical accuracy. The standalone
sampling/filter experiments remain exploratory and are not part of the main
pipeline. Install `wfdb` separately if running these scripts.

## Full PhysioNet validation

The full-dataset runner compares the same selected PPG channel with annotated
ECG across every record in the official PhysioNet PTT v1.1.0 manifest. The
default remains **red `pleth_2` at the original 500 Hz**, for comparability with
the initial single-record experiment. This source uses MAX30101 sensors, not
MAX30102. Other wavelengths can be selected explicitly with `--channel`.
This evaluates one chosen channel across all recordings, not all six channels.

```sh
.venv/bin/python -m pip install -r PhysioNet_PPG/requirements.txt
.venv/bin/python PhysioNet_PPG/download_physionet.py
.venv/bin/python PhysioNet_PPG/validate_all_physionet.py
```

The downloader caches the WFDB files (about 418 MB for 66 records) in
`PhysioNet_PPG/data`, skipping files whose published SHA256 checksum already
matches. The validator verifies every `.hea`, `.dat`, and `.atr` file before
analysis. Network access is needed only for downloading.

Results are saved in `PhysioNet_PPG/all_recordings_results`:

- `record_status.csv`: every attempted record, including failures and warnings.
- `all_window_comparisons.csv`: all complete 60-second windows with PPG/ECG
  statistics, signed and absolute differences, acceptance and rejection reasons.
- `agreement_summary.csv`: results for sitting, walking, running and pooled
  data, reported for all comparable windows and accepted windows separately.
- `coverage_by_activity.csv`: retained-window counts and fractions.
- `rejection_reasons.csv`: reasons for rejecting windows, grouped by activity.
- `agreement_by_activity.png` and `accepted_agreement.png`: error summaries
  and descriptive agreement plots.
- Per-record folders: comparison windows and detected/reference peak timestamps.
- `analysis_metadata.json`: source, versions, parameters and interpretation rules.

The accepted subset uses the **same main-pipeline variability checks**, with
additional requirements for normal ECG annotations and reference beat coverage.
Missing PPG samples are never interpolated: contiguous finite segments are
processed independently, and windows overlapping gaps or a one-second guard
around gaps are excluded. Complete trailing windows only are compared. No
interval correction, ectopic deletion, or quality-threshold tuning is performed.

Error is PPG minus ECG. pNN errors are percentage points. The primary MAE weights
windows equally; `mean_record_mae` weights record-level means equally. Report
coverage with accepted-subset errors: rejected windows must not disappear from
the assessment. Descriptive agreement limits use mean difference +/- 1.96 sample
SD; repeated windows from one subject are not independent, and these are not
confidence intervals or clinical acceptance limits. Agreement with ECG combines
PPG measurement/detection error with physiological PRV-versus-HRV differences.

